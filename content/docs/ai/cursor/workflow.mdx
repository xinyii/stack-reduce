> 好的工作流不是让 AI 写更多代码，而是让 AI 写对代码——先规划、再实现、后验证。

## Plan Mode：先规划后执行

Plan Mode 让 AI 先生成详细的执行计划，经你确认后再逐步实施。

### 启用方式

在 Composer（`Ctrl + I`）中，使用下拉菜单选择 Plan 模式，或直接在提示中要求 AI 先制定计划：

```
我想给项目添加用户认证功能，使用 NextAuth.js + GitHub OAuth。
先制定一个详细的实现计划，不要直接写代码。
```

### 工作流程

```
规划 → 确认 → 实现 → 验证
```

1. **AI 生成计划** — 列出需要修改的文件、创建的文件、实现步骤
2. **你审查并调整** — 修改不合理的部分、补充遗漏的需求
3. **AI 按计划实现** — 确认后 AI 逐步执行
4. **验证结果** — 运行测试或手动检查

<Callout>
复杂任务使用 Plan Mode 后完成率提升 60%，返工率降低 40%。当你能用一句话描述 diff 时（如修复拼写、添加日志），跳过规划直接做。
</Callout>

### 保存计划

推荐将计划保存到 `.cursor/plans/` 目录，便于团队共享和后续参考：

```
将计划保存到 .cursor/plans/auth-implementation.md
```

## Composer 多文件编辑

Composer（`Ctrl + I`）是 Cursor 最强大的多文件编辑工具，效率是 Chat 的 3 倍。

### 适用场景

| 场景 | 示例 |
|------|------|
| 跨文件 Bug 修复 | 修复一个涉及 3 个文件的状态管理 bug |
| 新功能开发 | 添加用户注册功能（路由 + 组件 + API + 数据库） |
| 大范围重构 | 将类组件迁移为函数式组件 |
| 代码迁移 | 从 Pages Router 迁移到 App Router |

### 操作技巧

- **精准引用上下文** — 用 `@` 符号引入相关文件，而非让 AI 自己猜
- **增量修改** — 一次只做一件事，不要在一个提示中塞入多个不相关的修改
- **检查 diff** — 每次 AI 修改后仔细检查 diff，尤其关注删除的代码
- **Checkpoint 回退** — 如果修改不满意，使用 Checkpoint 回退到之前的状态

## Debug Mode

Debug Mode 是 Cursor 内置的智能调试模式，可以自动定位问题根本原因。

### 使用方式

当遇到错误时，直接将错误信息粘贴给 AI：

```
运行 pnpm dev 时报错：

TypeError: Cannot read properties of undefined (reading 'map')
  at UserList (src/components/UserList.tsx:12:25)

帮我排查根本原因并修复。
```

### Debug 工作流

AI 会自动执行以下步骤：

1. **分析错误** — 解读错误信息和堆栈追踪
2. **定位代码** — 找到出错的具体位置和相关依赖
3. **提出假设** — 列出可能的原因（通常 2–3 个）
4. **验证假设** — 检查代码逻辑，排除不可能的原因
5. **实施修复** — 修改代码并解释修改原因

<Callout>
Debug 时提供完整的错误信息（包括堆栈追踪）远比只说"报错了"有效。截图也比文字描述更直观。
</Callout>

## Agent Review：AI 代码审查

Cursor 提供两种 AI 代码审查模式，在提交代码前发现潜在问题。

### Deep Review（深度审查）

适合 PR 准备合并前的全面检查：

```
对这次改动做一个深度代码审查，重点关注：
- 潜在的运行时错误
- 性能问题
- 安全隐患
- 边界情况处理
@Git
```

### Quick Review（快速扫描）

适合提交前的快速检查：

```
快速扫描一下我刚才的改动，有没有明显的问题？
@Git
```

### 审查结果处理

| AI 反馈类型 | 处理方式 |
|-------------|----------|
| 确定的 Bug | 立即修复 |
| 潜在的问题 | 评估后决定是否处理 |
| 风格建议 | 参考但不必全部采纳 |
| 误报 | 忽略，可在 Rules 中标注避免重复 |

## Fork Chat：对话分叉

完成计划制定后，使用 Fork Chat 从当前对话分叉出新会话进行实现。主对话保持上下文清晰，分叉会话专注于具体实现。

```
主对话（规划）
├── Fork 1：实现用户认证模块
├── Fork 2：实现权限管理模块
└── Fork 3：编写集成测试
```

## 并发任务

使用 `Ctrl + T` 可以新建并发聊天标签页，最多同时运行 3 个独立任务：

- Tab 1：实现新功能
- Tab 2：修复另一个 Bug
- Tab 3：编写文档

<Callout type="warn" title="注意">
并发任务可能同时修改同一文件导致冲突，建议并发任务操作不同的文件集。
</Callout>

## 常见反模式

| 反模式 | 症状 | 解决方案 |
|--------|------|----------|
| 大杂烩会话 | 一个对话处理多个不相关任务 | 每个任务用独立会话 |
| 反复纠正 | 连续纠正 AI 超过两次仍然不对 | 新建会话，重写更清晰的提示 |
| 盲目接受 | 不看 diff 直接 Accept All | 逐文件检查修改，关注删除的代码 |
| 过度依赖 AI | 让 AI 一次性完成整个功能 | 分阶段实现，每步验证 |
| 忽略上下文 | 不提供错误信息或相关文件 | 用 @ 引用文件，粘贴完整错误 |
| 无验证 | 不跑测试不看效果就提交 | 要求 AI 运行测试并验证 |
