> 好的工作流不是让 AI 写更多代码，而是让 AI 写对代码——先规划、再实现、后验证。

## Plan Mode：先规划后执行

在 Agent 面板切换到 Plan 模式（`Shift + Tab`），AI 先生成计划，确认后再实施：

```
规划 → 审查调整 → 确认实施 → 验证结果
```

推荐将计划保存到 `.cursor/plans/` 目录，便于团队共享。

<Callout>
当你能用一句话描述 diff 时（修复拼写、添加日志），跳过规划直接做。
</Callout>

## Debug Mode：系统化排查

将完整错误信息（含堆栈追踪）粘贴给 AI，它会自动：分析错误 → 定位代码 → 提出假设 → 验证排除 → 实施修复。

<Callout>
提供完整错误信息远比只说"报错了"有效，截图也比文字描述更直观。
</Callout>

## Agent Review：代码审查

| 模式 | 适用场景 | 示例提示词 |
|------|----------|------------|
| Deep Review | PR 合并前全面检查 | `对这次改动做深度审查，关注运行时错误、性能、安全和边界情况` |
| Quick Review | 提交前快速扫描 | `快速扫描我刚才的改动，有没有明显问题？` |

处理方式：确定 Bug → 立即修复；潜在问题 → 评估后决定；风格建议 → 参考即可。

## 并发任务

`Ctrl + T` 新建并发标签页（最多 3 个），也可通过 Fork Chat 从当前对话分叉出独立会话。

<Callout type="warn" title="注意">
并发任务可能同时修改同一文件导致冲突，建议操作不同的文件集。
</Callout>

## 常见反模式

| 反模式 | 解决方案 |
|--------|----------|
| 一个对话处理多个不相关任务 | 每个任务用独立会话 |
| 反复纠正超过两次仍不对 | 新建会话，重写更清晰的提示 |
| 不看 diff 直接 Accept All | 逐文件检查，关注删除的代码 |
| 让 AI 一次性完成整个功能 | 分阶段实现，每步验证 |
| 不跑测试不看效果就提交 | 要求 AI 运行测试并验证 |
